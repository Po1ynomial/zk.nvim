SETUP                                                              *zk-setup*

The plugin requires Neovim 0.12 or newer and a `zk` executable implementing
ZK editor protocol 2 and public data schema 2. The current development baseline
is zk 0.3.0 with archive format 3. Older protocols are not supported.

To initialize a new archive with the bundled archive-local agent skills: >sh

  zk init --agent-skills /path/to/archive
<
Ordinary `zk init` does not create `.agents`. Installed skills are user-owned,
and later `zk` commands leave them untouched.

Configure a personal archive to make archive commands available from every
buffer: >lua

  require("zk").setup({
    archive = "~/zettelkasten",
  })
<
The default language-server command is `{ "zk", "lsp" }`. The default CLI
command is `{ "zk" }`. Override either when `zk` is not on $PATH: >lua

  require("zk").setup({
    lsp_cmd = { "/path/to/zk", "lsp" },
    cli_cmd = { "/path/to/zk" },
  })
<
The `archive` option expands `~` and environment variables, resolves relative
paths against Neovim's current working directory, and validates the archive
before selecting it. The canonical selected path is readable as
`require("zk").archive`.

The plugin appends `--archive` with the selected root to both command arrays.
The configured archive starts one background `zk` language server during
setup. A nearer `zk.toml` above the current buffer takes precedence and gets
its own server when needed. Without `archive`, the plugin retains local-only
discovery.

Tinymist can remain attached to the same Typst buffer. The plugin makes
`zk.toml` a higher-priority Tinymist root marker than `.git`, so imports from
`../lib/` work even when the archive is not a Git repository.

The plugin validates both ZK protocol 2 and data schema 2 during initialization,
then validates schema-2 envelopes before using custom query results. Missing
or unsupported versions are rejected. Optional feature flags default to false.
Executable, plugin, protocol, data schema, and archive-format versions are
independent.

Neovim dynamic file watching is enabled for notes, zk.toml, and
templates/zettel.typ. Buffer writes and CLI creation/removal also send file
notifications. Saved template changes update tracking; unsaved template edits
do not. Invalid saved-schema reloads visibly report an error while retaining
the server's previous view. Ordinary template/library editing belongs to
Tinymist. The plugin does not require a presentation library to load an archive.

Set `decorations = false` to disable title extmarks. Set `mappings = false` to
disable all default mappings. Individual mapping values can also be replaced
or set to `false`.

==============================================================================
COMMANDS                                                        *zk-commands*

:ZkFind [query]                                      *:ZkFind*
    Search live Zettel metadata in the selected archive through
    `workspace/symbol` and present the results through |vim.ui.select()|. Open
    the selection in the window where the search began.

:ZkBacklinks                                         *:ZkBacklinks*
    Put all incoming authored reference locations for the current Zettel into
    the quickfix list.

:ZkDiagnostics                                       *:ZkDiagnostics*
    Put published live diagnostics for open notes from the selected `zk`
    language server into quickfix. This is not an archive-wide check.

:ZkCheck                                             *:ZkCheck*
    Run `zk check --format json` against saved archive state and put diagnostics
    into quickfix. A completed integrity check with exit status 1 still yields
    useful diagnostics. Positions use saved bytes, not modified buffer text.

:ZkNew                                               *:ZkNew*
    Run `zk new`, then edit the generated Zettel in the window where the
    command began. A modified prior buffer remains hidden with its changes
    intact.

:ZkRemove [ID]                                       *:ZkRemove*
    Run guarded removal for ID, or for the current Zettel when ID is omitted.
    Refuse while any canonical note buffer in the selected archive is modified.
    The CLI then checks saved incoming references, including self-references.
    Other editors' unsaved changes are not visible to this guard.

:ZkRefresh                                           *:ZkRefresh*
    Refresh title decorations in the current buffer.

:ZkSetArchive [path]                                 *:ZkSetArchive*
    Select another fallback archive for this Neovim session. Invalid paths
    leave the existing fallback and server unchanged. With no path, report
    the current fallback.

ZkFind, ZkNew, ZkCheck, ZkDiagnostics, and ZkRemove with an explicit ID work
from any buffer when a fallback is configured. ZkBacklinks, ZkRefresh, and
ZkRemove without an ID require a current Zettel.

==============================================================================
MAPPINGS                                                        *zk-mappings*

The defaults are buffer-local:

  gd              Follow a Zettel reference with `zk lsp`; use normal LSP
                  definition elsewhere.
  <leader>zf      Search Zettel.
  <leader>zb      Show backlinks.
  <leader>zd      Show Zettelkasten diagnostics.
  <leader>zn      Create a Zettel.

ZK creation, search selection, and definition navigation replace the buffer in
the invocation window. They preserve unsaved prior buffers as hidden and do
not create splits.

==============================================================================
COMPLETION                                                    *zk-completion*

After `@`, numeric text completes ID prefixes and other text searches Zettel
titles without regard to case. Accepting an item replaces the temporary query
with its ten-digit ID.

Tinymist owns dictionary-member completion, including category dictionaries.
No metadata field name has a built-in role. The plugin does not require or
configure a completion frontend.

`require("zk").filter_completion_items` is deprecated. It returns the original
items unchanged in every context, so existing frontend configurations no longer
intercept Tinymist results. Remove the helper from completion configuration.

==============================================================================
DECORATIONS                                                  *zk-decorations*

Decorations require archive-query and reference-title-decoration feature flags.
Resolved `@ID` ranges are concealed and replaced with core target-title virtual
text. A null title falls back to the target ID. Missing targets use the
`ZkMissingReference` highlight. The raw source
remains unchanged and becomes visible according to Neovim's conceal rules.

Decorations come from `zk lsp` queries. The Lua plugin recognizes narrow
source contexts for routing but does not extract metadata or keep an archive
graph.
